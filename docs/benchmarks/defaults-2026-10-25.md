# Arabic OCR defaults evaluation — 2026-10-25

The selected defaults are **200 DPI, grayscale PNG, a 2,339-pixel long-edge cap for image inputs without enlargement, and eight concurrent page operations per Drive account**. On 177 paired pages, the selected PNG images had 11.390% normalized character error rate (CER) and 22.518% normalized word error rate (WER). Compared with the earlier 200-DPI RGB JPEG 85 results, CER changed by −0.207 percentage points (95% CI [−0.354, −0.059]) and WER by −0.791 points ([−1.091, −0.507]). These are results from the Python evaluation harness; they are not measurements of the Rust CLI.

The [selected JSON aggregates](defaults-2026-10-25.json) retain the underlying precision, source-file SHA-256 hashes, software versions and reported size/request tables. The [scoring script](score-defaults.py) preserves the evaluation's cleanup and normalization functions. Datasets, page transcripts, raw request logs and upload-session URLs are not included. Benchmark artifacts are excluded from the published `tahweel-cli` crate.

## Applied defaults

| Setting | Default | Reason |
|---|---|---|
| PDF rendering | PDFium, 200 DPI | Both real datasets favored 200 over 150; higher resolutions did not improve pooled CER. |
| Image inputs | Long edge at most 2,339 px; no enlargement | A4 at 200 DPI; apply EXIF orientation before sizing. |
| Color and encoding | Grayscale, lossless PNG; DEFLATE level 6 | Lower paired error than RGB JPEG 85, within the byte budget. |
| Sharpening | Off | The tested mild sharpening increased CER. |
| Encoded size | At most 2,000,000 decimal bytes | Operational cap; all 177 final PNG images fit. |
| Oversized page | JPEG 95 → 85 → 75 → 60, then proportional resizing at JPEG 75 | Preserve dimensions first; see the policy below. |
| OCR language | `ar` | Small paired improvement; no English-word penalty observed. |
| Page operations per account | 8, including export and deletion | Fastest tested concurrency. |
| Request deadlines | 180 s total, 20 s connect | Practical margins for the observed tails; configurable total timeout. |
| Attempts and upload protocol | 5 attempts per HTTP operation; multipart | Keep the existing bounded retry policy and simple upload path. |

Start from oriented pixels at the selected resolution and color mode. If the chosen encoding exceeds the recognizer's byte limit, try JPEG 95, 85, 75 and 60 at unchanged dimensions, stopping at the first fit. A JPEG starting quality only tries ladder entries below it. If none fits, shrink each dimension by `min(0.90, 0.95 × sqrt(limit / encoded_bytes))` per step and encode at JPEG 75. Each resize samples the prepared source pixels, preserving aspect ratio apart from integer rounding; it never crops or decodes the preceding JPEG. Continue until the actual encoded bytes fit, or return an error if even a 1×1 image cannot fit. This fallback is an engineering policy; all 177 final validation images fit without needing it.

Uploads stay multipart. The evaluation recommended resumable uploads after stalls on the shared link, but [Google's upload guide](https://developers.google.com/workspace/drive/api/guides/manage-uploads) recommends multipart for small files up to 5 MB. The 2 MB product cap keeps uploads in that range, and multipart is substantially simpler. The longer total timeout gives margin over measured upload tails; it does not resolve packet loss or guarantee completion on every connection. The coordinator retained five attempts and one 180-second total request timeout; the harness allowed up to six attempts and its final recommendation used separate resumable-initiation/media/export/delete deadlines. Those harness recommendations are not the product defaults.

There are 177 distinct pages: 150 Arabic, 20 explicit Arabic/English and 7 Arabic/Latin. The English paragraph was written for this evaluation. The 14 source downloads totaled 339,347,849 bytes: NOD archives 42,122,660; Misraj shard/card 247,997,061; Tashkeela excerpts/card 48,426,723; fonts/licenses 771,504; NOD record metadata 29,901. KITAB and Qari were excluded because their dataset-card licenses were unclear. Original source URLs, hashes, exact excerpts and page selection remain in the archived harness manifests.

The harness used Python 3.13.14, pypdfium2 5.14.0 with PDFium 156.0.8076.0, Pillow 13.0.0 with RAQM, RapidFuzz 3.14.6 and NumPy 2.5.4. NOD physical dimensions follow its 300-DPI scans. Misraj physical sizes are unknown: its long edge was assigned 297 mm, so nominal DPI comparisons there are pixel-size comparisons. Synthetic text was shaped at 450 DPI, embedded in an A4 PDF, rendered at 300 DPI, degraded and wrapped as a scanned-image PDF. Degradation levels had 32/32/16 pages: none; +0.25° rotation, 0.35 px blur and noise standard deviation 1.5; or −0.55°, 0.6 px blur and noise 3.0. Scan JPEG qualities were 95/88/80. Ground truth is the text actually drawn. Every evaluation PDF page was rendered; no text layer was extracted.

The initial resolution screen used 72 pages (24 per dataset); confirmation added the remaining 105 at all four resolutions. A nested seeded sample of 54 pages (18 per dataset) compared RGB/grayscale × JPEG 60/75/85/95 or PNG compression 6 at 200 DPI. Pillow JPEG optimization was disabled and RGB subsampling was 4:2:0. Sharpening used paired repeat controls. Final validation compared `ar` with omission on identical encoded bytes for all 177 pages. Case selection and shuffled order were saved before the respective runs. Named successful recoveries replace failed transfers for accuracy only; original attempts remain in reliability counts.

The Rust implementation uses `image` 0.25.10, Triangle resizing and the shipped PDFium chromium/8111 build. The harness used Pillow/Lanczos for direct image sizing and a different PDFium version. JPEG quality and subsampling are encoder-specific; matching quality numbers or PNG compression level does not establish byte-for-byte rendering or OCR equivalence. The Rust JPEG call explicitly preserves the prepared grayscale or RGB pixel format.

## Scoring

Remove only the exact initial `\ufeff________________\r\n\r\n` wrapper, remove a remaining leading BOM, convert CRLF to LF and trim. Strict CER keeps punctuation, line breaks and diacritics; strict WER splits on whitespace. Normalized scores apply NFKC, remove Arabic marks in U+0610–U+061A, U+064B–U+065F, U+0670 and U+06D6–U+06ED and remove tatweel U+0640; fold `أإآٱ→ا`, `ؤ→و`, `ئ/ى→ي`, `ة→ه`; convert decimal digits to ASCII; and collapse whitespace. Bare hamza and punctuation remain. CER includes the resulting spaces. Both rates are Levenshtein edit distance divided by reference character/word count. Blank-reference outputs are described rather than assigned an informative percentage.

Tables report page-macro means, not pooled edit counts. Intervals are deterministic 2,000-resample percentile bootstrap intervals for the mean or paired difference, with NumPy seed 20261025. A change in percentage points is distinct from a relative percentage change. Error rates include reading order and transcription conventions as well as character recognition. The JSON retains unrounded values; displayed precision follows the evaluation's summaries.

## Standalone image sizing

The 47 Misraj originals had long edges of 715–5,925 pixels:

| Sizing path (RGB JPEG 85) | Pages | Normalized CER % | Normalized WER % | Mean bytes |
|---|---|---|---|---|
| Native, capped at 2,339; no enlargement | 47 | 7.800 | 14.858 | 235,049 |
| Force 2,339 long edge with Lanczos | 47 | 7.371 | 14.434 | 347,910 |
| PDFium at 200 DPI (assigned A4 long edge) | 47 | 6.749 | 13.848 | 334,711 |

Direct Lanczos forcing to 2,339 changed CER by −0.429 points versus native/capped images ([−1.366, +0.465]) while increasing mean bytes from 235,049 to 347,910. Direct Lanczos was 0.622 points worse than PDFium at the same long edge ([0.158, 1.221]). The initial PDFium advantage of 1.051 points therefore does not demonstrate a general benefit from image enlargement. Cap large images and preserve smaller originals.

These are 96 workloads, not 96 distinct pages. Each worker performs upload → export → delete sequentially, so eight workers imply at most eight in-flight requests. ## Reproduction and limits

The archived evaluation is in `~/repositories/_fleet/tahweel/notes/defaults/`. It contains `README.md`, `prepare.py`, `cases.py`, `extras.py`, `evaluate.py`, `analyze.py`, `diagnostics.py`, `report_tables.py`, `audit_results.py`, `pyproject.toml`, `uv.lock`, `sources.json`, the fixed manifests and saved results. This repository contains only the compact summaries and scorer, so replaying the original OCR experiment requires that archive or reconstructing its corpus and harness from the stated design.

To check cleanup/normalization or score a prepared reference against an exact UTF-8 Drive export, without any Google calls:

```sh
uv run --no-project --python 3.13 docs/benchmarks/score-defaults.py --selftest
uv run --no-project --python 3.13 docs/benchmarks/score-defaults.py reference.txt export.txt
```

To regenerate summaries from the archived run, without rerunning OCR:

```sh
. ~/repositories/_fleet/tahweel/env.sh
cd ~/repositories/_fleet/tahweel/notes/defaults
uv run --locked python -I evaluate.py selftest
uv run --locked python -I analyze.py
uv run --locked python -I analyze.py --phase resolution-all
uv run --locked python -I analyze.py --phase language
uv run --locked python -I analyze.py --phase size
uv run --locked python -I diagnostics.py
uv run --locked python -I report_tables.py
uv run --locked python -I audit_results.py
```

For a fresh experiment, use a separate run marker/result directory and new case IDs. Follow the archive's preparation commands (`prepare.py download`, `prepare.py real`, `prepare.py synthetic`, `cases.py resolution`), then its saved phase manifests: resolution and resolution-confirm; encoding and named recoveries; paired sharpening plus direct-image-resize controls; language; size-final. Ordinary phases used at most eight workers; size-final used four. The harness reads the designated account through the fleet environment, enforces an eight-request ceiling and a 6,000-upload budget, and exports/deletes each uploaded Doc. Run its cleanup phase before and after OCR. Existing completed IDs are skipped, including failures; repeats need new IDs. Preserve original failures alongside recoveries.

The final audit verified 1,935 completed case records, 1,925 successful OCR/export/delete round trips, 1,957/6,000 upload attempts and a peak of 8/8 requests. It rehashed 1,600 encoded images and recalculated all four scores from saved exports. Ten completed failed cases and four successful explicit recoveries remain; ten upload starts had no terminal response after interruptions. At 2026-10-25T17:23:17.712759+00:00 the Drive audit found zero run-owned files and both original baseline files still present.

The synthetic pages overlap excerpts from four works; they are not 80 independent books. Bootstrap intervals are conditional on these sampled pages, exploratory and unadjusted for multiple comparisons. The staged resolution-then-encoding design does not measure every interaction, and final validation reuses the corpus rather than holding out new books. Reading-order failures on columns/spreads can dominate pooled scores. Results concern one account, one date, one shared network and three size-probe contents; they do not establish universal accuracy, image limits or throughput. No new OCR evaluation was run while applying these Rust defaults.
